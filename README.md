# Monitor Production

Monitor Production (моніторинг виробництва) — внутрішня веб-система фіксації параметрів вимірювань та контролю якості продукції (ВТК) на виробничій лінії.

---

## Архітектурний огляд

Система побудована за модульним контейнеризованим принципом і складається з трьох ключових компонентів:
1. Реляційна база даних (PostgreSQL 16): Зберігає метадані деталей, результати замірів, статуси придатності, системні логи та посилання на збережені медіафайли.
2. Веб-сервер та Reverse Proxy (Nginx): Приймає весь вхідний трафік на портах 80/443, напряму роздає клієнтську статику (HTML/CSS/JS) та директорію завантажених фотографій (/uploads/), а також проксує запити до API на бекенд.
3. Бекенд-сервіс (Python / FastAPI): Обробляє бізнес-логіку валідації допусків параметрів, формує записи в БД, виконує безпечне збереження фотографій на диск та віддає REST API.

### Схема проходження трафіку
```
[ Клієнт / Комп'ютер на виробничій лінії ]
           │
           │ HTTP (порт 80 / 443)
           ▼
     [ Nginx:80 ] ──────────────────────┐
      │         │                       │
      │         │ /api/* (проксі)       │ /uploads/*
      │         ▼                       ▼
      │    [ Backend:8000 ]    [ Директорія ./uploads/ ]
      │         │                       ▲
      │         │ запис метаданих       │ збереження фото
      │         ▼                       │
      │    [ PostgreSQL:5432 ]          │
      │                                 │
      └───────> роздача статики (frontend/)
```

## База даних

У проєкті використовується PostgreSQL 16. Схема складається з двох ключових сутностей: каталогу моделей продукції (`products`) та журналу зафіксованих випробувань/вимірювань кожного конкретного екземпляра (`measurements`).

---

### 1. Таблиця `products` (Довідник продукції / моделей)

Зберігає базову інформацію про лінійку виробів, їх артикули, тип та технічні характеристики у форматі JSONB.

| Назва стовпця | Тип даних | Обмеження / Індекси | Опис |
| :--- | :--- | :--- | :--- |
| `id` | `BIGSERIAL` | `PRIMARY KEY` | Унікальний ідентифікатор моделі продукції |
| `name` | `VARCHAR(255)` | `NOT NULL` | Назва виробу |
| `description` | `TEXT` | `NULL` | Розширений опис виробу |
| `type` | `VARCHAR(64)` | `NOT NULL` | Тип продукції (наприклад: `Світильник`, `Щит`) |
| `article` | `VARCHAR(100)` | `UNIQUE, NOT NULL` | Виробничий артикул (SKU) |
| `characteristics` | `JSONB` | `DEFAULT '{}'::jsonb` | Специфікація та номінальні характеристики (JSON) |

---

### 2. Таблиця `measurements` (Журнал вимірювань та контролю якості)

Фіксує проходження виробу через виробничі робочі місця, результати випробувань, часові мітки та фотофіксацію.

| Назва стовпця | Тип даних | Обмеження / Індекси | Опис |
| :--- | :--- | :--- | :--- |
| `id` | `BIGSERIAL` | `PRIMARY KEY` | Унікальний ідентифікатор запису вимірювання |
| `product_id` | `BIGINT` | `NOT NULL, FK` | Зовнішній ключ до таблиці `products(id)` |
| `barcode` | `VARCHAR(128)` | `NOT NULL, INDEX` | Унікальний штрихкод/серійний номер конкретного виробу |
| `q_tests_data` | `JSONB` | `DEFAULT '{}'::jsonb` | Фактичні дані випробувань |
| `time` | `TEXT` | `NULL` | **Щось подумати над часом** |
| `notes` | `TEXT` | `NULL` | Примітки та службові коментарі оператора |
| `photo_path` | `VARCHAR(512)` | `NULL` | Відносний шлях до файлу фотографії на диску (`/uploads/...`) |
| `release_date` | `DATE` | `NULL` | Дата випуску продукції |
| `created_at` | `TIMESTAMPTZ` | `DEFAULT NOW()` | Системний час внесення запису в базу |

---

### Зв'язки та індексація (Constraints & Indexes)

1. **Зв'язок `1:N` (Один до багатьох):**
   - `measurements.product_id` ➔ `products.id` з правилом `ON DELETE RESTRICT` (забороняє видалення типу продукції, якщо за ним уже зафіксовані фактичні вимірювання).
2. **Індекси під промисловий сценарій:**
   - **`btree (barcode)`** у таблиці `measurements` — гарантує миттєвий пошук деталі при скануванні сканером штрихкодів на лінії.
   - **`btree (product_id)`** — для швидких вибірок історії вимірювань за певною моделлю.
   - **`gin (q_tests_data)`** та **`gin (characteristics)`** — GIN-індекси для швидкої фільтрації та пошуку за конкретними полями всередині JSONB-структур.

## Web

Вебморда крутиться на Nginx за 80 портом  

---
Зараз поки планується що при вході на сайт вводиш номер робочого місця і сервер сам підтягує тобі інтерфейс. Тобто буде наготовано багато шаблонів які будуть показуватись на виробничій лінії. Якому місцю який шаблон / параметри шаблону налаштовуються на стороні адміністрування

---
На стороні `адміністрування` налаштовується яке вікно буде надіслано на кожне робоче місце (кількість робочих місць) і тай усьо  
Буде ще вкладка `моніторинг` де показано план/факт значення, ще якась інформація і якась качечка раз на пів години вибігає з-за вікна і крякає
